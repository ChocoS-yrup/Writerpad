12단계 미진행 실기기 검증 절차
작성일: 2026-07-29

대화에서 명시적으로 확인된 항목

- 같은 줄 겹침 충돌 발생
- iPad 로컬 TXT가 즉시 서버본으로 덮어써지지 않음
- `충돌 해결 필요` 표시
- 충돌 해결 화면 진입
- 해결 결과 저장
- Windows에서 최종 해결 결과 수신
- 약 7,000자 문서에서 원본 탭 전환은 즉시 반응

아직 완료 보고가 없거나 별도로 확인해야 하는 실기기 검증은 아래 항목이다.
테스트끼리 상태가 섞이지 않도록 항목마다 새 문서를 사용하는 것이 좋다.


============================================================
공통 준비
============================================================

1. 테스트 전 iPad와 Windows 모두 같은 계정·같은 작품을 사용한다.
2. Windows 프로그램과 iPad 앱의 동기화가 모두 완료될 때까지 기다린다.
3. 테스트 문서는 실제 원고가 아닌 별도 문서로 만든다.
4. 기준 본문은 아래처럼 줄을 명확하게 나눈다.

공통 첫 줄
기준 문장
공통 마지막 줄

5. 양쪽 기기에서 위 본문이 동일한지 확인한다.
6. Windows에서는 문서 편집을 끝낸 뒤 반드시 해당 문서를 닫아 편집 잠금을 해제한다.
7. iPad를 오프라인으로 만들 때는 앱을 종료하지 않고 Wi-Fi를 끈다.


============================================================
1. 미해결 충돌의 재실행 보존과 네 원본 정확성
============================================================

이 검증은 12-3과 12-4의 재실행 보존을 함께 확인한다.

[충돌 만들기]

1. iPad와 Windows에서 공통 본문이 같은지 확인한다.
2. iPad의 Wi-Fi를 끈다.
3. iPad에서 둘째 줄만 다음처럼 바꾼다.

아이패드 로컬 문장

4. iPad 화면에 변경된 문장이 그대로 보이는지 확인한다.
5. Windows에서 같은 문서의 둘째 줄을 다음처럼 바꾼다.

윈도우 서버 문장

6. Windows 동기화 완료를 확인한다.
7. Windows에서 문서를 닫는다.
8. iPad Wi-Fi를 켠다.
9. `충돌 해결 필요`가 표시될 때까지 기다린다.

[재실행 확인]

10. 충돌 해결 화면을 아직 열지 않은 상태에서 iPad 앱을 완전히 종료한다.
11. iPad 앱을 다시 실행한다.
12. 같은 작품을 연다.
13. 여전히 `충돌 해결 필요`가 표시되는지 확인한다.
14. iPad 본문이 여전히 `아이패드 로컬 문장`인지 확인한다.
15. `충돌 해결`을 누른다.

[원본 확인]

16. `기준본`에서 둘째 줄이 `기준 문장`인지 확인한다.
17. `내 로컬본`에서 둘째 줄이 `아이패드 로컬 문장`인지 확인한다.
18. `서버 최신본`에서 둘째 줄이 `윈도우 서버 문장`인지 확인한다.
19. `병합 후보`에 네 원본과 충돌 구분선이 정상적으로 표시되는지 확인한다.
20. 위쪽 원본 탭을 눌러도 아래쪽 `해결 결과`가 멋대로 변경되지 않는지 확인한다.
21. 화면을 취소한 뒤에도 `충돌 해결 필요`가 유지되는지 확인한다.

[정상 결과]

- 앱 재실행 후에도 충돌 상태가 사라지지 않는다.
- Base·Local·Remote가 정확히 구분된다.
- 현재 iPad TXT는 로컬 편집본 그대로 유지된다.
- 단순히 위쪽 탭만 누른 것으로 해결 결과가 변경되지 않는다.


============================================================
2. `내 로컬본` 선택 해결
============================================================

별도의 새 테스트 문서에서 다시 같은 줄 충돌을 만든다.

1. `충돌 해결` 화면을 연다.
2. 세로 화면이라면 `내 로컬본` 탭을 선택한다.
3. `‘내 로컬본’을 아래 해결 결과에 적용`을 누른다.
4. 아래 `해결 결과`가 정확히 iPad 로컬본으로 바뀌었는지 확인한다.
5. 오른쪽 위 `이 결과로 해결`을 누른다.
6. `충돌 해결 필요`가 사라지는지 확인한다.
7. 동기화 완료까지 기다린다.
8. Windows에서 같은 문서를 다시 연다.
9. Windows 본문이 iPad 로컬본과 완전히 같은지 확인한다.
10. iPad 앱을 완전히 종료했다가 다시 실행한다.
11. 해결된 충돌이 다시 나타나지 않는지 확인한다.

[정상 결과]

- 최종 본문은 iPad 로컬본이다.
- Windows도 동일한 본문으로 수렴한다.
- 재실행 후 충돌 상태가 다시 생기지 않는다.


============================================================
3. `서버 최신본` 선택 해결
============================================================

또 다른 새 테스트 문서에서 같은 줄 충돌을 만든다.

1. `충돌 해결` 화면을 연다.
2. `서버 최신본` 탭을 선택한다.
3. `‘서버 최신본’을 아래 해결 결과에 적용`을 누른다.
4. 아래 해결 결과가 정확히 Windows 서버본인지 확인한다.
5. `이 결과로 해결`을 누른다.
6. iPad 본문이 서버 최신본으로 바뀌는지 확인한다.
7. Windows와 iPad 양쪽에서 같은 본문인지 확인한다.
8. iPad를 완전히 종료했다가 다시 실행한다.
9. 충돌 상태가 사라진 채 유지되는지 확인한다.

[정상 결과]

- 사용자가 명시적으로 서버본을 적용한 뒤에만 로컬 TXT가 서버본으로 바뀐다.
- 양쪽 기기가 서버본으로 수렴한다.
- 해결 이력이 재실행 후에도 유지된다.


============================================================
4. 직접 편집한 병합 결과 저장
============================================================

또 다른 새 문서에서 같은 줄 충돌을 만든다.

1. 충돌 해결 화면을 연다.
2. `병합 후보`를 선택한다.
3. `‘병합 후보’를 아래 해결 결과에 적용`을 누른다.
4. 아래 `해결 결과` 편집기에서 모든 충돌 구분선을 제거한다.
5. 최종 본문을 다음처럼 명확한 고유 문장으로 만든다.

아이패드와 Windows 내용을 직접 정리한 최종 결과

6. 위쪽 원본 탭을 여러 번 전환한다.
7. 아래 직접 편집한 결과가 바뀌지 않는지 확인한다.
8. `이 결과로 해결`을 누른다.
9. Windows에서 최종 문장이 정확히 수신되는지 확인한다.
10. iPad와 Windows를 각각 재실행해도 최종 결과가 유지되는지 확인한다.

[정상 결과]

- 위쪽 탭은 보기만 변경한다.
- 아래 해결 결과만 저장된다.
- `=======` 등의 충돌 구분선이 사용자가 남긴 경우에만 실제 본문에 포함된다.
- 양쪽 기기가 직접 편집한 최종본으로 수렴한다.


============================================================
5. 비겹침 자동 rebase와 rename 수렴
============================================================

대화에서 비겹침 병합 자체는 관찰됐지만, 제목 변경과 본문 변경이 하나의 문서 UUID로
수렴하는지는 별도로 확인하는 것이 좋다.

[준비]

본문:

아이패드 수정 위치
공통 중간 줄
Windows 수정 위치

문서 이름:

UUID 수렴 테스트

[실행]

1. 양쪽 기기의 기준 상태가 동일한지 확인한다.
2. iPad Wi-Fi를 끈다.
3. iPad에서 첫째 줄을 다음처럼 수정한다.

아이패드가 수정한 첫째 줄

4. Windows에서 문서 제목을 다음처럼 바꾼다.

UUID 수렴 테스트 서버 이름

5. Windows에서 셋째 줄을 다음처럼 수정한다.

Windows가 수정한 셋째 줄

6. Windows 동기화 완료를 확인하고 문서를 닫는다.
7. iPad Wi-Fi를 켠다.
8. 동기화 완료까지 기다린다.

[확인]

9. `충돌 해결 필요`가 나타나지 않는지 확인한다.
10. iPad 바인더 제목이 `UUID 수렴 테스트 서버 이름`으로 바뀌는지 확인한다.
11. iPad 본문에 첫째 줄과 셋째 줄의 수정이 모두 들어 있는지 확인한다.
12. 기존 제목과 새 제목의 문서가 중복으로 생기지 않았는지 확인한다.
13. iPad에서 본문 끝에 다음 문장을 추가한다.

UUID 수렴 최종 확인

14. 다시 동기화한다.
15. Windows의 이름이 바뀐 동일 문서에서 이 문장을 수신하는지 확인한다.

[정상 결과]

- 제목은 Windows 변경을 사용한다.
- 본문은 양쪽의 비겹침 변경을 모두 포함한다.
- 문서가 두 개로 복제되지 않는다.
- iPad의 후속 변경이 Windows의 이름 변경된 동일 문서로 도착한다.

이 결과가 나오면 사용자 화면에서 UUID를 직접 보지 않아도 동일 UUID 수렴을
간접적으로 확인할 수 있다.


============================================================
6. 화면 회전과 크기 변경
============================================================

충돌이 열린 상태에서 진행한다.

1. iPad를 세로 방향으로 둔다.
2. 원본 비교가 `기준본·내 로컬본·서버 최신본·병합 후보` 탭으로 표시되는지 확인한다.
3. 원본 하나를 아래 해결 결과에 적용한다.
4. 해결 결과 끝에 `회전 전 입력`을 적는다.
5. 키보드를 내리지 않은 상태로 iPad를 가로로 돌린다.
6. 가로 화면에서 네 원본 비교 패널이 나란히 표시되는지 확인한다.
7. `회전 전 입력`이 사라지지 않았는지 확인한다.
8. 각 패널의 `결과에 적용` 버튼이 해당 패널의 내용만 적용하는지 확인한다.
9. 다시 세로로 돌린다.
10. 해결 결과와 스크롤 상태가 비정상적으로 초기화되지 않는지 확인한다.
11. 가능하면 Split View로 앱 폭을 좁혔다가 다시 넓힌다.
12. 좁은 화면에서는 탭형, 넓은 화면에서는 비교 패널형으로 안전하게 바뀌는지 확인한다.

[정상 결과]

- 회전 중 직접 작성한 해결 결과가 유실되지 않는다.
- 좁은 화면에서는 탭형, 충분히 넓으면 비교 패널형이다.
- 원본은 계속 읽기 전용이다.
- 버튼과 편집기가 겹치거나 화면 밖으로 잘리지 않는다.


============================================================
7. 외장 키보드와 한글 조합
============================================================

외장 키보드 또는 Magic Keyboard를 연결한다.

[저장 단축키]

1. 충돌 해결 화면을 연다.
2. 해결 결과 편집기를 선택한다.
3. 한글로 다음 문장을 입력한다.

외장 키보드 한글 조합 확인

4. 마지막 글자의 조합이 끝난 것을 확인한다.
5. `Command + S`를 누른다.
6. 화면이 닫히고 충돌 해결이 저장되는지 확인한다.
7. Windows에서 문장이 수신되는지 확인한다.

[취소 단축키]

8. 다른 테스트 문서로 새 충돌을 만든다.
9. 해결 결과를 일부 편집한다.
10. `Esc`를 누른다.
11. 충돌 해결 화면만 닫히는지 확인한다.
12. 현재 로컬 원고가 해결 후보 내용으로 덮어써지지 않았는지 확인한다.
13. `충돌 해결 필요` 상태가 계속 유지되는지 확인한다.

[정상 결과]

- `Command + S`: 현재 해결 결과를 저장한다.
- `Esc`: 저장하지 않고 화면을 닫는다.
- 취소한 해결 후보가 로컬 TXT에 반영되지 않는다.
- 한글 조합 중 글자가 잘리거나 다른 문서로 전환되지 않는다.


============================================================
8. VoiceOver 검증
============================================================

`설정 → 손쉬운 사용 → VoiceOver`에서 VoiceOver를 켠다.
가능하면 손쉬운 사용 단축키를 설정해 빠르게 끄고 켠다.

1. 충돌 해결 화면을 연다.
2. 오른쪽으로 쓸어 읽기 순서를 확인한다.
3. 다음 정보가 순서대로 읽히는지 확인한다.

   - 문서 이름
   - 충돌 개수
   - 서버 revision
   - `원본 비교`, `읽기 전용`
   - 각 원본 이름
   - 원본 적용 버튼
   - `해결 결과`, `편집 가능`
   - 해결 결과 편집기
   - `이 결과로 해결`

4. 각 원본이 `읽기 전용`이라고 안내되는지 확인한다.
5. 원본 영역을 두 번 탭해도 키보드가 나타나거나 내용이 수정되지 않는지 확인한다.
6. `해결 결과 편집기`를 선택한다.
7. 이 영역에서만 편집이 가능한지 확인한다.
8. 원본 적용 버튼의 설명이 “아래 편집 가능한 해결 결과에 복사”한다는 의미로 읽히는지 확인한다.
9. `이 결과로 해결`을 실행한다.
10. 저장 중 버튼을 반복 실행할 수 없는지 확인한다.

[정상 결과]

- 읽기 순서가 화면 흐름과 일치한다.
- 읽기 전용 원본과 편집 가능한 해결 결과가 명확히 구분된다.
- 버튼 이름만 듣고도 어느 원본이 적용되는지 알 수 있다.
- 저장 버튼이 중복 실행되지 않는다.


============================================================
9. 오프라인 상태에서 해결 결과 저장
============================================================

네트워크 복구 구현 전에도 로컬 queue 보존 여부를 확인하는 보강 테스트다.

1. 충돌 해결 화면까지 온라인으로 진입한다.
2. 해결 결과를 최종 문장으로 편집한다.
3. iPad Wi-Fi를 끈다.
4. `이 결과로 해결`을 누른다.
5. 앱이 오류를 내더라도 해결 결과나 기존 로컬 원고가 사라지지 않는지 확인한다.
6. 앱을 완전히 종료한다.
7. Wi-Fi를 켜지 않은 상태로 다시 실행한다.
8. 로컬 문서가 열리고 편집 가능한지 확인한다.
9. Wi-Fi를 켠다.
10. 동기화가 재개되면 Windows에서 최종 해결 결과를 확인한다.
11. 같은 해결 operation이 중복 적용되거나 문서가 복제되지 않는지 확인한다.

현재 네트워크 복구 문제 때문에 15초 이상 장기 대기하거나 영구 대기가 발생한다면,
그 결과는 12단계 병합 실패가 아니라 별도의 네트워크 복구 작업의 재현 자료로 기록한다.


============================================================
권장 실행 순서
============================================================

1. 미해결 충돌 재실행 보존
2. 내 로컬본 선택 해결
3. 서버 최신본 선택 해결
4. 직접 편집 병합 해결
5. 비겹침 rebase와 rename 수렴
6. 화면 회전
7. 외장 키보드
8. VoiceOver
9. 오프라인 해결 저장

1~5번은 12단계 완료를 확정하는 핵심 실기기 검증이다.
6~8번은 12-4 화면 요구사항 검증이다.
9번에서 발생하는 장기 대기 문제는 별도의 네트워크 안전 복구 작업에서 처리한다.
