[3] 판별표 (1)~(5)
------------------------------------------------------------

(1) pullNow start와 finishPull의 reqID 짝

판정: 관찰된 pull은 짝이 맞음. C4는 이번 표본에서 배제.

- 15:24:47.531 pullTask create reason=pullNow-start
- 15:24:48.202 pullTask clear reason=finishPull
- 15:26:17.794 pullTask create reason=pullNow-start
- 15:26:18.439 pullTask clear reason=finishPull

주의
- 현재 로그는 pullRequestID 증가를 별도 generation 이벤트로 기록한다.
- task 로그 행 자체에는 reqID가 없으므로 시간 순서와 직전 pullRequestID로
  대응시켰다.
- 이번 표본에서 start만 있고 finish가 없는 pull은 관찰하지 못했다.


(2) reconnectAttempt 0 -> 1 -> 0 왕복

판정: 직접 판정 불가. 다만 재연결 반복은 확실함. 3번 최우선.

- 1번 로거는 reconnectAttempt 값을 직접 기록하지 않는다.
- task 생성 간격으로 1초, 2초, 5초, 10초 계열 backoff 진행은 확인했다.
- subscribed 성공 및 reconnectAttempt=0 복귀는 이번 세션에서 확인하지 못했다.
- SyncV2RealtimeStartRace가 반복 timeout되고 reconnectTask가 반복 생성됐다.


(3) RealtimeConnectGate acquire/release 균형과 waiters 증가

판정: 관찰 구간은 균형. C6 증거 없음.

- waiters는 최대 1까지 올라간 뒤 0으로 복귀했다.
- release-handoff 뒤 최종 release가 나왔고 isHeld=false, waiters=0이 됐다.
- waiters의 단조 증가는 관찰하지 못했다.

대표 순서
- acquire isHeld=true waiters=0
- acquire-wait isHeld=true waiters=1
- release-handoff isHeld=true waiters=0
- release isHeld=false waiters=0


(4) blocked by stale sentinel 반복

판정: 직접 문자열은 없지만 간접 증거상 반복 없음. 2번 수정 효과 확인.

- 1번 로거에는 "blocked by stale sentinel" 전용 이벤트가 없다.
- reconnectTask는 각 backoff에서 create -> clear 뒤 다음 create가 나왔다.
- 취소된 첫 sentinel 때문에 이후 예약이 영구 봉쇄되는 패턴은 없었다.
- 그러나 스피너는 재발했으므로 C1만으로 전체 증상을 설명할 수 없다.


(5) operation superseded

판정: 관찰 없음. C7 미확정.

- event=authOperationSuperseded는 관찰 구간에 나오지 않았다.
- 따라서 이번 표본만으로 6번의 C7을 확정할 수 없다.

------------------------------------------------------------
[5] 로그 파일 보존 상태와 도구 제약
------------------------------------------------------------

- Console.app은 ChoCo와 subsystem 필터를 설정했지만 이 환경에서는 앱의
  Logger.info 행을 표시하지 않고 0개 메시지로 남았다.
- devicectl --console에서는 동일 Logger.info 행이 정상적으로 출력됐다.
- devicectl 출력을 리디렉션하거나 script/tee로 감싸면 Apple CoreDeviceService가
  초기화 실패를 반복해 전체 스트림 파일 저장이 불가능했다.
- Apple log collect --device-udid는 attached device 로그 수집에 root 권한을
  요구해 자동 수집이 거부됐다.
- sudo 및 사용자 비밀번호 입력은 시도하지 않았다.
- 따라서 이 문서에는 Codex가 직접 수신한 핵심 원시 로그 행을 발췌 보존했다.
