# 2-1 로컬 경로와 파일명 정책

## 저장 위치

실제 앱의 작품 루트는 Application Support 아래에 둔다.

```text
Application Support/
└─ WriterPad/
   └─ Projects/
      └─ 프로젝트명/
         └─ 집필모드/
```

`ProjectPathResolver`는 테스트에서 임시 `Projects` URL을 주입할 수 있으며 실제 앱에서는 위 위치를 사용한다.

## 새 작품 고정 구조

```text
집필모드/
├─ 메인/
│  ├─ 원고/
│  ├─ 캐릭터/
│  ├─ 설정집/
│  ├─ 메모장/
│  ├─ 흐름정리/
│  ├─ 복선/
│  ├─ 장소/
│  └─ 휴지통/
├─ 백업/
│  ├─ 자동저장/
│  ├─ 복원전/
│  └─ 충돌/
└─ 설정.json
```

화면의 `흐름 정리`는 디스크의 `흐름정리`에 대응한다. `플롯`, `메인 스토리 틀`, 루트 `휴지통`, `백업/전환직전`은 새 작품에 만들지 않는다. 기존 Windows 작품에서 발견하면 가져오기 단계에서 사용자 자료로 보존한다.

## 이름 거부 규칙

- 빈 이름, `.`과 `..`
- `< > : " / \ | ? *`
- NUL, 탭, 줄바꿈을 포함한 Unicode 제어 문자
- 공백이나 마침표로 끝나는 이름
- `CON`, `PRN`, `AUX`, `NUL`
- `COM1`~`COM9`, `LPT1`~`LPT9`

예약 이름은 대소문자와 확장자를 무시한다. 따라서 `con.txt`, `AUX.TXT`, `Lpt1.자료`도 거부한다.

## 충돌 기준

같은 부모의 이름은 NFC 정규화 후 대소문자를 구분하지 않는 키로 비교한다. `Plot.txt`와 `plot.txt`, NFC 한글과 분해형 한글은 충돌한다. 실제 문서 정체성은 이름이 아니라 `document_id`다.

`설정.json`에는 최초 `project_name`을 기록한다. macOS 파일 시스템이 한글 이름을 분해형으로 반환해도 같은 프로젝트 재실행과 새 정규화 충돌을 구분하는 데 사용한다. 기존 설정 파일은 구조를 다시 확인할 때 덮어쓰지 않는다.

## 길이 설정

현재 임시 상한:

- 이름 한 구성 요소: 255 UTF-16 단위
- 집필모드 내부 상대 경로: 1,024 UTF-16 단위

Windows v2 저장 루트가 확정되면 `PathPolicy.Limits`만 조정한다. 현재 값은 최종 Windows 호환 길이를 의미하지 않는다.

## 루트 탈출 방지

상대 경로를 구성 요소별로 검사한 다음 표준화·심볼릭 링크 해석을 거쳐 작품 루트 아래인지 다시 확인한다. 다음 입력은 거부한다.

- `/tmp/file.txt`, `C:\\file.txt` 같은 절대 경로
- `../`와 중간 `..`
- 빈 경로 구성 요소
- 작품 안의 심볼릭 링크를 이용한 외부 디렉터리 접근

`.txt`는 실제 파일명에 유지하고 바인더 표시 이름에서만 마지막 확장자를 숨긴다.
