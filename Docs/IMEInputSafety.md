# 한글 IME 안전장치 4-2

## 불변 조건

- `markedTextRange`가 존재하면 조합 중이다.
- 조합 중에는 외부 본문을 UITextView에 적용하지 않는다.
- 조합 중 문서 선택은 즉시 실행하지 않고 마지막 요청 하나를 pending transition으로 보관한다.
- 조합 완료 뒤 현재 문서 초안을 확정한 다음 pending 문서를 로딩한다.
- 문서 전환에 SwiftUI `.id`를 사용하지 않고 같은 `SmartTextView` coordinator를 유지한다.
- 키보드 언어 강제 변경, 키 재전송, Windows IME 제어 코드는 사용하지 않는다.

## 포커스 상태

`EditorFocusStateMachine`은 `idle`, `focused`, `composing`, `backgrounded`, `restoring`을 구분한다.

- 포커스가 있었던 편집기만 foreground 복귀 때 first responder를 요청한다.
- background 중 조합이 끝나도 pending 문서 전환을 실행하지 않는다.
- foreground 복귀 후 pending 전환을 처리하고, 활성 문서가 남아 있으면 포커스를 복원한다.
- 포커스 요청은 증가하는 토큰으로 전달하며 본문을 재주입하지 않는다.
- SwiftUI `updateUIView` 안에서는 `becomeFirstResponder`나 `resignFirstResponder`를 동기 호출하지 않는다.
- 비활성 편집기의 responder 반납은 다음 메인 루프로 미루고, 그사이 같은 패널이 다시 활성화되면 세대 토큰으로 취소한다.
- `markedTextRange`가 남은 동안에는 비활성화 요청이 와도 responder를 강제로 반납하지 않는다.
- 좌우 활성 패널은 사용자 탭이나 바인더 선택이 결정하며, UIKit의 지연된 포커스 복원 콜백이 활성 패널을 덮어쓰지 않는다.

## 자동 검증

- 조합 중 외부 문서·버전 적용 보류
- 여러 문서 요청 중 마지막 요청만 유지
- 조합 완료 후 pending 전환과 이전 문서 초안 보존
- background 중 pending 유지와 foreground 후 처리
- 포커스가 있었던 편집기만 foreground에서 복원
- 빈 반대쪽 패널 활성화 중 responder 반납이 SwiftUI 갱신에 재진입하지 않음
- 예약된 responder 반납 전 원래 패널이 다시 활성화되면 안전하게 취소
- 이미 열린 문서 알림을 닫아도 사용자가 선택한 활성 패널 유지
- UI에서 한글·이모지 일반 입력과 빠른 문서 로딩 경로

## 실제 iPad 검증

자동화의 `typeText`는 실제 `markedTextRange` 수명과 외장 키보드 조합을 완전히 재현하지 못하므로 iPad Pro 11-inch (M5)에서 다음 항목을 확인했다.

1. 소프트웨어 두벌식 키보드로 `값이`, `앉다`, `읽고` 등 겹받침 포함 문장을 입력한다.
2. 음절 조합 직후 다른 화를 빠르게 선택하고 이전 화의 마지막 글자와 새 화의 첫 글자가 보존되는지 확인한다.
3. 001화와 002화를 빠르게 10회 왕복하며 각 화의 첫 한글이 영문으로 바뀌거나 사라지지 않는지 확인한다.
4. 한글 입력 직후 홈 화면으로 나갔다가 복귀해 첫 글자를 입력한다.
5. 가능하면 Magic Keyboard와 일반 Bluetooth 키보드에서도 2~4를 반복한다.
6. 가로 분할에서 왼쪽 원고에 커서를 둔 뒤 빈 오른쪽 패널을 누르고, 바로 상단 버튼과 바인더 항목이 눌리는지 확인한다.

검증 결과:

- 소프트웨어 키보드 한글 조합, 겹받침, 빠른 화 전환, 앱 복귀 후 첫 입력이 정상 동작했다.
- Bluetooth 키보드의 일반 입력과 한글 입력이 정상 동작했다.
- 키를 길게 누를 때 반복 입력이 되지 않는 현상은 WriterPad뿐 아니라 다른 앱에서도 동일했다. 앱의 키 처리 결함이 아니라 현재 iPad 외장 키보드 반복 입력 설정 상태로 분류했다.
- 별도 Magic Keyboard는 제공되지 않아 독립적으로 재검증하지 않았으며, 실제 사용 키보드인 Bluetooth 경로로 외장 키보드 검증을 완료했다.

현재 상태: 4-2 실제 iPad 검증 완료.

분할 편집기 포커스 프리즈 수정은 자동 회귀 테스트를 완료했으며, 6번 실기기 재검증을 기다린다.
