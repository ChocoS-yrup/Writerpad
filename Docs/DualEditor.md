# 좌우 듀얼 편집기 4-6 계약

## 상태와 라우팅

- 기본은 단일 편집기이며 가로·충분한 폭에서 상단 분할 버튼으로 좌우 편집기를 연다.
- 왼쪽 문서, 오른쪽 문서, 활성 편집기, 분할 여부, 각 커서를 `EditorWorkspaceState`로 작품별 저장·복원한다.
- 바인더 선택은 활성 편집기로 전달한다. 반대쪽에 같은 `document_id`가 열려 있어도 활성 편집기에 다시 열 수 있다.
- 작업공간 저장소는 같은 `document_id`가 좌우 상태에 동시에 기록되는 것을 허용한다.

## 원고와 IME 안전

- 두 편집기는 각각 별도 `SmartTextView`와 coordinator를 사용하므로 Undo, 커서, 선택, 스크롤이 독립적이다.
- 같은 문서를 양쪽에 열면 본문 변경은 즉시 공유하고, 반대쪽 커서·선택은 UTF-16 편집 증감만큼 보정한다.
- 세션의 초안 저장소는 공유해 한쪽에서 닫은 미저장 초안을 다른 쪽에서 다시 열어도 디스크의 이전 본문으로 되돌아가지 않는다.
- 활성 편집기가 바뀌면 기존 UITextView는 first responder를 내려놓고 새 활성 편집기만 포커스를 요청한다.
- marked text 조합 중에는 편집기 전환과 분할 열기·닫기를 거부하고 한글 확정 후 재시도를 안내한다.

## 폭과 닫기 경계

- 분할 선호와 실제 화면 표시를 분리한다. 세로 또는 좁은 폭에서는 활성 편집기 하나만 표시하되 분할 선호와 양쪽 초안은 보존하고, 다시 가로·충분한 폭이 되면 자동 복원한다.
- 최소 지원 버전은 iPadOS 17.6이며, 주 실기기 검증 환경은 iPad Pro 11-inch (M5)의 iPadOS 26.x다. iPadOS 26 전용 API는 가용성 검사 뒤에만 사용한다.
- `UIScreen.coordinateSpace`의 전체 화면 방향만 분할 표시 판정의 단일 입력으로 사용하므로 iPadOS 창 최소화·최대화가 일시적인 창 크기 이벤트를 반복해도 세로 화면에서 분할 표시가 켜지지 않는다.
- 작품 진입 직후에는 작업공간 복원이 끝난 뒤 바인더와 편집기를 표시해 복원 결과가 새 선택을 덮어쓰는 경합을 막는다.
- 분할 닫기 전에 양쪽 초안과 커서를 공유 초안 저장소 및 작업공간 저장소에 전달한다.
- 커서·작업공간 상태 저장이 실패하면 분할 닫기와 작품 변경을 중단한다.
- 실제 TXT 즉시 저장과 저장 실패 재시도는 5단계 저장 coordinator가 이 경계에 연결한다. 따라서 4-6 완료 시점의 디스크 저장 보장은 부분 검증 상태다.

## 자동 검증

- 이미 반대쪽에 열린 문서를 활성 편집기에도 열 수 있음
- 저장소 수준의 동일 `document_id` 좌우 상태 저장·복원
- 한글·이모지를 포함한 본문 변경 시 반대쪽 UTF-16 커서 위치 보정
- 두 편집기 사이 미저장 초안 전달과 현재 문서 상태 독립
- 별도 UITextView Undo 이력 독립
- iPad Pro 11-inch (M5) 가로 UI에서 분할 열기, 001화·002화 배치, 001화 양쪽 열기, 활성 편집기 전환, 분할 닫기
- 작품 목록으로 나갔다 다시 열 때 좌우 문서·활성 편집기·분할 상태 복원
- iPadOS 26 실기기에서 가로 분할 → 세로 → 가로 자동 복원, 세로 창 최소화·최대화와 반복 크기 변경 중 분할 표시·버튼 상태 안정성
- 관련 단위 테스트와 iPad Pro 11-inch (M5) 시뮬레이터 검증 통과
- Mac Catalyst arm64 호환 빌드 통과
