# iPad 일반 검증: 화면·계정·로컬 상태 연결 결과

사용자의 “아이패드 측 진행”에 따라 기존 기록 모듈을 실제 앱의 계정 상태, 작품 연결, 화면 수명 및 로컬 검사에 연결했다. 이번 후보는 송수신이 잠긴 준비 화면까지 구현한 검토 후보다. 실기기 설치·기기 데이터 접근·실서버 요청은 모두 0회다.

## 화면과 실제 상태 연결

설정의 서버 계정 및 작품 연결에 “일반 시험 작품 검증”을 표시한다. “계정·로컬 기준 확인”은 기존 로그인과 권한, 시험 작품 연결의 계정 소유자 및 서로 다른 local/server UUID, 대기열, SQLite와 파일을 검사한다. 이 버튼은 로그인 복원·refresh·새 권한 발급·서버 조회를 수행하지 않는다.

통과 문구는 “계정·로컬 기준 확인 완료. 송수신은 잠겨 있습니다.”다. 화면 이탈·앱 비활성화·인증/작품 연결/작품 수명 변경·기존 권한 만료 시 준비가 무효화된다. 유효 시간은 최대 5분이며 기존 로그인 권한의 만료를 넘기지 않는다. “준비 중단”으로도 폐기할 수 있다. 일반 검토 빌드에서 이전 시험 작품의 실행 화면과 서비스는 노출·생성하지 않는다.

AppEnvironment에서 실제 인증 서비스, binding epoch, project lifecycle epoch, 실제 저장소 URL과 workspace를 주입한다. 선택 작품의 upload queue가 idle이고 일반 대기·주의·재시도 항목이 0인지 확인한다. 완료된 과거 기록은 허용한다.

## 로컬 기준 검사

동기화 SQLite와 SwiftData 메타데이터 SQLite를 읽기 전용 트랜잭션으로 열어 전체 사용자 테이블의 논리 해시를 계산한다. 다른 작품의 큐를 포함한 행 변경도 이후 비교에서 감지한다. checkpoint·마이그레이션·수리·저장은 수행하지 않는다. 선택 작품의 폴더 11개·정렬 12개, 대조 문서 revision/hash, 고정 부모 폴더·문서 이름·서버 경로·정렬 revision/children을 별도로 검사한다.

workspace의 파일 내용과 빈 폴더를 포함한 경로를 비교하며 심볼릭 링크·열거 실패·크기 제한 초과를 거부한다. 최초 단계에서 같은 이름의 파일이 이미 있으면 준비를 거부한다. 파일 내용은 UTF-8 원문 바이트와 대조한다.

기준 계획은 기존 `general-body-20260912-v1`이다. 본문·UUID·순서는 이전 Windows 준비 문서와 대조한 값을 유지한다. 이 표는 로컬 단계 판정이며 실서버 최신 상태를 조회한 결과가 아니다.

## 기록 모듈 연결

실행 객체 생성 함수에 실제 계정·화면·작품 연결·기존 권한 검사와 새 SQLite/파일 비교를 전달했다. 앱 전용 Application Support의 `GeneralValidation/general-body-20260912-v1`을 고정 기록 루트로 사용한다. 준비 검사만으로 기록 파일을 만들지는 않는다. 실행 객체 생성 때만 0700 디렉터리를 준비하며, 기존 모듈의 단계별 단독 생성·fsync·재사용 금지를 유지한다.

같은 단계 기록이 있으면 “이 단계의 실행 기록이 있습니다. 기록 확인 전에는 재실행할 수 없습니다.”로 중단한다. 화면의 재준비는 기존 기록을 지우거나 새 루트로 우회하지 않는다. 모의 HTTP 검사에서는 실제 화면 모델이 생성한 실행 객체로 첫 요청을 기록하고, 화면 이탈 또는 실제 메타데이터 변경 이후 다음 요청/응답이 차단되는 것을 확인했다.

## 아직 남은 실행 구성

이번 화면은 실제 수신·저장·송신을 호출하지 않는다. 실행 객체의 로컬 기준은 준비 시점의 전체 snapshot으로 고정되어 있다. 정상 수신 반영 또는 본문 저장으로 발생하는 허용된 로컬 상태 전환, 완전한 원격 snapshot 판정, 반영 이후 완료 callback을 실제 단계 실행 서비스에 연결해야 한다. 이를 생략하고 현재 객체로 송수신을 실행하면 정상적인 로컬 변경도 거부될 수 있다.

인증·handshake·최종 조회 요청 목록과 호출 예산, 실제 큐에서 생성한 요청 바이트의 고정도 남아 있다. 데이터 요청의 기존 ReceiveValidation/BodyValidation 잠금과 일반 범위 제한은 유지된다. 기록 모듈의 GET 3 / document_commit 1 / GET 3 구성은 전체 실서버 호출 예산을 확정한 것이 아니다.

Windows에는 이 ZIP을 준비 진척으로 전달할 수 있다. 이전 검토에서 지적한 정렬 요청의 실제 operation/batch/build ID 연결 결과와 양쪽 최종 실행 후보를 대조한 뒤, 구체적인 백업·설치·실서버 실행 범위를 승인받는다. 현재 실기기에서 추가로 누를 버튼은 없다.
