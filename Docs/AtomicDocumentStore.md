# UTF-8 TXT 원자적 저장 계약

## 적용 범위

`LocalDocumentStore` actor는 작품의 `집필모드` 루트 안 `.txt` 본문만 읽고 저장한다. 문서 본문은 UTF-8 TXT가 단일 원본이며 SwiftData에 본문을 복제하지 않는다.

## 저장 API

- 입력: `projectID`, `documentID`, 검증된 상대 경로, 본문 문자열, `generation`
- 결과: 작품·문서 ID, 상대 경로, SHA-256, 실제 파일 수정 시각, `generation`
- 읽기: 손실 변환 없이 엄격한 UTF-8로 해석하며 잘못된 바이트는 오류로 보고한다.

## 원자적 교체 순서

1. 작품 루트와 `.txt` 상대 경로를 검증한다.
2. 원고와 같은 폴더에 고유한 `.writerpad-save-*.tmp`를 배타 생성한다.
3. UTF-8 바이트 전체를 단축 쓰기가 끝날 때까지 반복하고 `fsync`한다.
4. 저장된 바이트의 SHA-256과 수정 시각을 담은 재조정 표식을 작품 루트에 저장한다.
5. 같은 파일 시스템의 `rename`으로 임시 파일을 정상 원고 위치로 교체한다.
6. SwiftData의 경로·해시·수정 시각을 갱신하고 재조정 표식을 지운다.

임시 파일 생성, 쓰기, flush, 재조정 표식 생성, 교체 중 어느 곳에서 실패해도 기존 정상 원고는 그대로 남는다. 액세스 권한 거부, 저장 공간 부족, UTF-8 해석 실패, 교체 실패는 사용자가 구분할 수 있는 오류로 올라간다.

## 동시 저장과 generation

- 같은 `documentID`의 저장은 이전 저장의 파일 교체와 메타데이터 반영이 끝난 후 시작한다.
- 이미 접수한 최신 generation보다 작거나 같은 요청은 저장하지 않는다.
- 다른 문서는 서로의 저장 순서에 묶이지 않는다.

## 재실행 복구

TXT 교체는 성공했지만 SwiftData 갱신이 실패하면 `.writerpad-reconcile-*.json`을 남긴다. 다음 실행에서 대상 TXT의 SHA-256가 표식과 일치할 때만 메타데이터를 다시 반영한다. 해시가 다르거나 표식이 손상됐으면 원고를 수정하지 않고 점검 대상으로 남긴다.

재실행 정리는 임시 파일을 원고로 승격하지 않는다. 기본 1시간보다 오래된 잔여 임시 파일만 삭제하고 최근 파일은 진행 중일 수 있어 보존한다.

## 자동 검증

실제 원고는 사용하지 않고 매 테스트마다 새 임시 폴더를 만든다. 빈 파일, 한글, 이모지, 대용량, 잘못된 UTF-8, 알려진 SHA-256, 동시 저장, 오래된 generation, 5개 실패 지점, 권한·용량 오류, 재실행 재조정을 검사한다.
