# iPad 격리 재실행 검증 보완 — 2026-09-12

`general-body-20260912-v1`과 실행 때 생성하는 operation/batch ID를 유지한다. 이 변경은 SwiftData 저장 이력 때문에 발생했던 격리 예측 불일치를 처리한다. 실기기 설치·서버 접근·관문·보류 변경은 포함하지 않는다.

## 검증 방식

일반 경계 검사의 전체 동기화 DB·메타데이터·파일 해시는 유지하며 DB 테이블의 열 이름·자료형·제약 정보도 해시에 포함한다. 이력 테이블 전체를 제외하거나 변경 후 상태를 조건 없이 기준으로 채택하지 않는다.

실제 로컬 변경을 실행하기 전에 원본과 격리 결과로 `GeneralValidationMetadataReplay`를 만든다. 원본 상태가 변하면 계획 생성을 중단한다. 제품 행과 다른 작품의 행, 기존 ATRANSACTION·ACHANGE·ATRANSACTIONSTRING 행은 보존해야 한다. 새 이력도 행 수·키·시각 외 모든 값이 격리 결과와 일치해야 한다.

허용하는 차이는 두 가지뿐이다.

- 격리 결과에 이미 존재하는 새 ATRANSACTION 행의 ZTIMESTAMP: 실제 로컬 실행 시작부터 완료까지의 시각이어야 한다. 최대 300초이며 과거 이력의 시각 변경은 거부한다.
- Z_PRIMARYKEY에서 TRANSACTIONSTRING 행의 Z_MAX: 원본 값 또는 격리 실행이 관측한 두 슬롯 예약 값만 허용한다. 중간 값·감소·추가 증가·다른 엔터티 카운터 변경은 거부한다.

이 처리는 관측한 SQLite 이력 구조에만 적용한다. 알 수 없는 스키마나 다른 자동 생성 차이는 계속 중단 사유다. 검증이 통과하면 그 결과의 전체 해시를 고정하고, 이후 경계에서는 다시 전체 해시가 같아야 한다. 기존·신규 이력의 사후 변경도 감지한다.

## 제품 코드 연결

`GeneralValidationPlanningCopy.predictedCheckpoint`에서 원본 보존 확인과 메타데이터 비교 규칙을 포함한 단일 변경 계획을 만든다. `makeTransition`을 통해 수신·저장·완료 처리·최종 수신의 실제 제품 코드에 연결한다. 저장된 본문과 아직 revision 1인 대기 상태도 별도로 복제할 수 있다.

완료 처리의 예상값은 실제 경계가 수락한 응답으로 별도 산출하도록 `GeneralValidationIsolatedStorage.completeAccepted`를 추가했다. 응답 revision이 2가 아니면 복제본 변경 전 거부한다. 계획용 함수를 호출하는 것만으로 응답의 네트워크 수락이나 서버 송신 권한이 생기지는 않는다.

동일한 의미의 요청이 JSON 키 순서 때문에 서로 다른 해시를 갖는 문제도 발견해 일반 검증 adapter의 요청 직렬화를 sortedKeys로 고정했다.
