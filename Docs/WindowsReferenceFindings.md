# Windows 집필 모드 참조 소스 조사 결과

- 조사일: 2026-07-15
- 참조 소스: `공유/`
- 테스트 작품: `집필모드/`
- 조사 방식: 읽기 전용

## 제공 상태

- 집필 모드 핵심 Python 소스와 단위 테스트가 제공됐다.
- 실제 `.env`, 인증서, 개인 키 파일은 발견되지 않았다.
- `.env.example`만 존재한다.
- `tests/__pycache__`와 `.pyc`는 불필요한 생성물로 Git에서 제외한다.
- Supabase 구현 파일은 제공되지 않았으며 1~7단계 범위에는 필요하지 않다.

## 테스트 작품 구조

- `메인/원고/1권/001화.txt`부터 `025화.txt`까지 존재한다.
- `메인/원고/2권/026화.txt`부터 `050화.txt`까지 존재한다.
- 총 50개 TXT 중 2개는 테스트 내용이 있고 48개는 빈 파일이다.
- 파일은 UTF-8로 읽을 수 있다.
- macOS에서 한글 파일명이 분해형 Unicode로 보이므로 NFC 정규화 비교가 필요하다.
- 실제 휴지통 경로는 `메인/휴지통`이다.
- Windows 레거시 폴더 `메인/플롯`, `백업/전환직전`이 존재한다.

## 코드에서 확인한 호환 규칙

| 항목 | Windows 현재 구현 | iPad 1~7단계 결정 |
|---|---|---|
| 프로젝트 루트 | `작품목록/프로젝트명/집필모드` | Application Support 내부에서 같은 상대 구조 유지 |
| 원고 | `메인/원고/N권/NNN화.txt` | 동일 |
| 휴지통 | `메인/휴지통` | 동일 경로 채택 |
| 플롯 | `메인/플롯` 고정 생성 | 새 작품에는 생성하지 않고 가져오기 시 보존 |
| 전환직전 백업 | `백업/전환직전` | 새 작품에는 생성하지 않고 가져오기 시 보존 |
| TXT 인코딩 | UTF-8 강제 | 동일 |
| 원자 저장 | `.tmp` 쓰기·flush·fsync·`os.replace` | 같은 의미의 Swift 원자 교체 구현 |
| 루트 밖 경로 | `commonpath` 검사 | 표준화 후 프로젝트 루트 재검증 |
| 새 권 | 25개 순차 생성 | 임시 폴더에서 25개 성공 후 승격 |
| 전체 추출 정렬 | 권과 무관하게 화 번호 정렬 | 동일 |
| 300자 중단 | 공백 제외 길이로 계산 | 최신 결정인 공백 포함 길이로 계산 |
| 자동저장 지연 | 5초 유휴 타이머 | 800ms |
| IME | Windows 강제 전환·키 재전송 코드 존재 | iPad에는 이식하지 않음 |

## 재사용할 개념

- UTF-8 읽기·쓰기
- 임시 파일과 원자 교체
- 프로젝트 루트 밖 경로 거부
- 원고 화수 자연 정렬
- 새 권 계산식과 25개 화 범위
- 휴지통 원래 위치 기록
- 복원 전 현재본 백업
- 자동저장 이력과 diff
- 전체·부분 추출이 원본을 바꾸지 않는 테스트

## 그대로 이식하지 않을 부분

- PyQt UI와 Windows 전용 IME 강제 제어
- `메인/플롯`과 메인 스토리 틀 고정 노드
- 5초 자동저장 지연
- 공백 제외 300자 판정
- 서버 락·heartbeat·동기화 결합
- 임시 폴더 없는 새 권 생성
- 서버 및 AI 설정이 섞인 `config.json`

## 2단계에서 사용할 fixture 기준

제공된 테스트 작품 자체는 Git에 넣거나 수정하지 않는다. 필요한 구조만 새 임시 fixture로 생성하고 다음을 자동 검증한다.

- 1권 001~025화와 2권 026~050화 인식
- `메인/휴지통` 매핑
- `메인/플롯`·`백업/전환직전` 원형 보존
- UTF-8 파일과 빈 파일 처리
- Unicode NFC 정규화 후 중복 검사
- 원본 폴더 전후 해시 불변
