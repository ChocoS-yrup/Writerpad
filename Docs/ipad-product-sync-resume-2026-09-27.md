# 실사용 동기화 재개 준비 — 2026-09-27

## 범위와 원인

앞 단계의 작품별 활성화·다중 문서 재시도 변경과 같은 `codex/ipad-product-sync-settings`에서 작업한다.
복구 진단 앱의 수동 확인이나 백업은 요구하지 않았다. 실제 iPad 설치·실서버 송수신·서버 변경은 하지 않았다.

기존 일반 송신기는 SQLite에 저장된 대기 변경이 있으면 서버 기준을 다시 확인할 수 있다.
그러나 인증/작품 전환이나 재시작 뒤, 파일 인계만 남고 SQLite 큐에는 아직 들어가지 않은 변경은
기준 준비의 진입 조건을 충족하지 못했다. 설정의 재시도는 handshake만 복원하고 계속 미연결로 남았다.

## 구현

- 설정의 `저장 기록 연결 및 재시도`에 읽기 전용 재개 준비를 연결했다.
- 기존 서버 기준 승인이 유효하면 그대로 사용한다. 승인이 없으면 현재 계정·연결 소유자·활성 작품·
  ID_BASED handshake·전경·사용자 설정을 확인한 뒤 서버 작품 활성 상태와 기준을 읽는다.
- 저장된 마지막 서버 기준 → 서버 1차 조회 → 서버 2차 조회 → 저장된 기준 재조회를 비교한다.
  모두 일치할 때만 기준 승인을 복원한다. 본문 pull, 파일 교체, 새 UUID/요청 생성,
  기존 요청 claim, 임의 revision 갱신, 구조 충돌 자동 해결은 하지 않는다.
- 파일 인계용 저장소 읽기를 분리했다. 기존 송신 재개의 `일반 대기 변경 필수` 조건은 유지한다.
  일반 큐가 비었을 때는 다른 미전송 작업이 없어야 하며, 기존 UUID 계약 기준이 있어야 한다.
  빈 작품이나 메타데이터가 불완전한 LEGACY 작품을 빈 비교 결과로 승인하지 않는다.
- 계정·연결·작품 수명·handshake·화면·전역 설정·관문 변화와 취소를 조회 사이에도 확인한다.
  설정 화면의 취소 세대를 스레드 안전한 epoch로 전달한다. 승인 직전 마지막 비동기 작업 이후에도
  권한을 확인하며, 실패 시 업로드/수신 조정기의 점유를 반환한다.
- 서버 기준 불일치 시 성공으로 표시하지 않고 본문과 저장 기록을 남겼다는 안내를 제공한다.

이 준비는 송신 성공 자체가 아니다. 준비 뒤 파일 인계를 큐에 기록하고 기존 dispatcher와 sender가
별도로 최종 권한·서버 상태·요청 무결성을 검사한다. 서버가 달라졌을 때 자동 덮어쓰지 않는다.
전체 자동 재개 스케줄러를 새로 만든 것이 아니라, 기존 일반 앱의 명시적 재시도 경로를 보완했다.

## 검증 범위

합성 원격 transport와 실제 TXT·SQLite를 사용한다. 재실행 케이스는 SQLite 연결과 transient
handshake/인증/조정기/송신기/저장소를 재생성하며, SwiftData fixture는 메모리에 유지한다.
실제 프로세스 강제 종료·실기기·실서버 검증으로 집계하지 않는다.

추가 검사:

- 작품 전환, 같은 계정 재로그인, 저장소 재생성 후 파일 전용 문서 2개를 재연결하고 송신.
- 준비 단계의 commit 요청 0건, 본문·메타데이터·마지막 서버 기준 불변.
- 서버 기준 불일치 및 두 조회 사이의 변경은 인계 파일의 bytes까지 보존.
- 기준 조회 중 인증·연결·작품 수명·화면 이탈·관문·전체 설정·비활성·handshake 변경 8종 차단.
- 서버 휴지통 상태와 조회 실패 차단, 정상 서버로 돌아온 뒤 명시적 재시도 성공.

## PR 최종 점검 보완

설정의 파일 인계 준비가 실패하면 기존 SQLite 요청의 재시도도 호출되지 않던 순서 문제를 수정했다.
이미 서버에 반영됐으나 응답을 잃은 요청은 서버 기준이 전진해 있으므로, 파일 인계 기준 비교와
별개로 기존 sender의 receipt 검증·복구가 가능해야 한다. 계정·연결·관문·활성 작품·handshake 확인 뒤
기존 큐의 재시도를 먼저 요청하고 파일 인계를 준비한다. 새 송신 권한을 부여하거나 요청을 재작성하지 않는다.

회귀 검사는 합성 응답 유실 요청과 별도 파일 인계를 함께 만든다. 서버 기준 불일치 안내를 유지하면서
dispatcher가 기존 요청의 receipt만 수용하고, 새 commit 없이 별도 인계 파일 bytes와 본문을 유지하는지 확인한다.
위 536개 결과는 이 순서 보완 전 단계의 기록이며, PR 최종 검증은 별도 묶음 기록을 따른다.
