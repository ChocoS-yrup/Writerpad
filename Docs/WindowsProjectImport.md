# Windows 작품 가져오기 — 2-4

## 사용자 흐름

1. 작품 목록의 `Windows 작품 가져오기`에서 작품 폴더 또는 `집필모드` 폴더를 선택한다.
2. 앱이 security-scoped resource 접근을 검사 동안만 유지하며 전체 트리를 읽는다.
3. 치명 오류와 경고가 분리된 검사 보고서를 표시한다.
4. 치명 오류가 없고 사용자가 경고를 확인한 경우에만 가져오기를 시작한다.
5. 앱 내부 숨김 임시 프로젝트로 전부 복사하고 UUID·SHA-256 메타데이터를 만든다.
6. 파일 복사와 SwiftData 일괄 등록이 모두 성공하면 정식 작품으로 승격한다.

검사와 가져오기 모두 원본에 쓰기·이름 변경·삭제 작업을 하지 않는다. 검사 뒤 원본 내용이나 구조가 달라지면 지문이 달라지므로 가져오기를 중단하고 재검사를 요구한다.

## 선택 가능한 폴더

- `<작품명>/집필모드`를 포함한 작품 컨테이너
- `집필모드` 폴더 자체
- `메인`과 `백업`이 바로 들어 있는 집필모드 루트

`설정.json`에 `project_name`이 있으면 이를 작품명으로 사용하고, 없으면 선택한 구조에서 작품명을 유도한다. 작품명은 Windows 이름 정책과 기존 작품의 대소문자·NFC 충돌 검사를 통과해야 한다.

## 검사 보고서

치명 오류는 가져오기를 막는다.

- UTF-8이 아닌 TXT
- `메인`, `메인/원고`, `백업` 필수 구조 누락
- 중복 작품과 전체 권을 통틀어 중복된 화 번호
- 정규 `N권/NNN화.txt` 접두사 규칙을 벗어난 원고 경로
- 읽을 수 없는 항목, 심볼릭 링크, 금지 이름
- 대소문자·Unicode NFC 정규화 후 이름 충돌

경고는 원형 보존할 자료나 새 복사본에서 보완할 항목을 알린다.

- 숨김 파일과 알 수 없는 사용자 파일
- 선택적 표준 폴더 또는 `설정.json` 누락
- `메인/플롯`, `메인 스토리 틀`
- `백업/전환직전`

플롯과 메인 스토리 틀은 iPad 고정 카테고리로 승격하지 않는다. `전환직전`을 `복원전`과 합치지도 않는다. 모두 선택 당시 상대 경로에 일반 레거시 사용자 자료로 남긴다.

## 거래와 복구

가져오기 표식은 복사 중, 임시 완성, 메타데이터 등록, 정식 승격 단계를 기록한다. 임시 프로젝트 안에서 누락된 선택적 표준 폴더를 만든 다음 모든 폴더와 UTF-8 TXT에 안정적인 UUID를, TXT에는 SHA-256을 부여한다. 작품과 문서 메타데이터는 하나의 SwiftData 저장으로 등록한다.

일반 실패가 발생하면 임시·정식 복사본과 해당 작품의 SwiftData 메타데이터를 모두 제거한다. 앱 중단으로 표식이 남으면 다음 시작 시 파일과 메타데이터 수를 대조해 완료된 승격만 인정하고 나머지는 롤백한다. 복구 자체가 실패하면 표식을 삭제하지 않고 위치를 오류로 보고한다.

## 자동 검증

실제 제공 원고는 수정하거나 fixture로 복제하지 않는다. 테스트마다 별도 임시 작품을 만들어 다음을 검증한다.

- 정상 작품의 원본 전후 전체 바이트·디렉터리 불변
- 비 UTF-8, 중복 화, 잘못된 권, 읽기 실패 보고
- 400화 트리 전체 검사
- 중간 복사 실패와 메타데이터 등록 뒤 실패의 완전 롤백
- 검사 후 원본 변경 시 재검사 요구
- 플롯과 전환직전 백업의 경고·경로 보존
- 가져온 문서 UUID 고유성과 TXT SHA-256 생성
- 1,000화·화 제목 허용과 Unicode 유사 숫자 거부
