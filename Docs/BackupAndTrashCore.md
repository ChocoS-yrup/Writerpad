# 6단계 백업·복원·휴지통 무결성 코어

## 저장 형식

- 백업 본문은 UTF-8 TXT, 메타데이터는 같은 UUID 이름의 JSON으로 분리한다.
- 자동·전환·닫기·구조 변경·수동 백업은 `백업/자동저장`, 복원 직전은
  `백업/복원전`, 충돌 예약 사건은 `백업/충돌`에 저장한다.
- 메타데이터에는 `backup_id`, 작품·문서 ID, 당시 상대 경로, 생성 시각,
  SHA-256, 사유, 보관 지정 여부를 기록한다.
- 자동 성격의 같은 해시 연속 백업은 기존 스냅샷을 재사용한다. 복원 전,
  구조 변경 전, 충돌, 명시적 수동 백업은 같은 해시여도 생략하지 않는다.

## 보존 정책

- 자동 백업 여부·최대 보관 수·보존 기간은 사용자 1명의 모든 작품에 공통으로 적용한다.
- 기존 작품별 정책 파일은 전역 정책이 없을 때 최초 접근 작품에서 1회 가져오고 삭제하지 않는다.
- 보관 지정본은 정책과 관계없이 유지한다.
- 문서별 최근 24시간은 최신 30개(설정 가능), 그 이전 보존 기간 안에서는
  UTC 날짜별 최신 1개를 유지한다.
- 삭제 실패는 원고 저장 성공을 되돌리지 않으며 항목별 정리 오류로 남긴다.
- 손상되거나 범위를 벗어난 설정은 기본값(자동 백업 on, 30개, 30일)으로 복구한다.

## 안전 복원 순서

1. 편집기의 현재 텍스트를 기존 원자 저장소로 즉시 저장한다.
2. 저장된 현재본을 `백업/복원전`에 강제 백업한다.
3. 선택 백업의 작품 ID, 문서 ID, 안전한 상대 경로, UTF-8, SHA-256을 검증한다.
4. 기존 원자 저장소로 선택 백업 본문을 교체하고 메타데이터를 갱신한다.
5. 로컬 복원 완료 사건만 미래 동기화 경계에 전달한다.

선택 백업 검증이나 교체가 실패하면 1단계에서 저장된 현재본이 그대로 남고,
복원 전 백업도 보존된다.

## 휴지통 트랜잭션

- 휴지통 이동 전에 원래 부모 ID·경로·사용자 순서·삭제 시각을 별도 기록한다.
- 복원은 원래 위치 또는 지정 폴더를 지원하고 `BinderRuleService`를 거친다.
- 이름 충돌은 기존 파일을 덮어쓰지 않고 안전한 대안 이름을 오류에 포함한다.
- 영구 삭제는 확인 플래그가 필수이며, 항목을 휴지통 내부 격리 경로로 먼저
  이동한 뒤 메타데이터를 제거한다. 중단 시 바인더 저널로 롤백 또는 재실행 복구한다.
- 휴지통 비우기는 항목별 성공과 실패를 분리해 보고한다.

## Terra UI 구간

- 백업 이력·읽기 전용 미리보기·비동기 diff 화면 구현
- 복원, 보관 지정/해제, 백업 삭제·확인 화면 구현
- 휴지통 상위 항목 표시, 원래/선택 위치 복원, 영구 삭제 확인,
  비우기 부분 실패 결과 화면 구현
- 설정 화면의 자동 백업, 최대 보관 수, 보존 기간 저장·오류 표시 구현
- iPad Pro 11-inch (M5) 실기기에서 휴지통 즉시 갱신·계층 표시·전역 백업 설정 공유 확인 완료
- 백업 미리보기·diff 원고 불변, 복원 결과·복원 전 백업·재실행 유지를 같은 실기기에서 확인 완료
