# NormalEditor 진단 구조 비교 기준 갱신

## 목적과 범위

A 복구 시험의 저장본은 올바르지만 예전 SQLite 구조와 서버의 다른 시험 항목이
달라 `NORMAL_TARGET_MISMATCH`가 발생했다. 일반 수신은 저장 대기 항목이 있으면
차단되며, 전체 수신을 강제로 실행하면 시험 범위를 벗어난 본문까지 취급하게 된다.

진단 화면에 명시적 **구조 비교 기준 갱신 · 본문 유지** 동작을 추가한다.
이 동작은 서버에서 조회·검증한 구조 메타데이터를 로컬 저널의 비교 기준으로만
보관한다. SQLite 구조/내용 기준이나 실제 TXT를 바꾸지 않고, 다른 문서의 본문을
받거나 해당 문서가 동기화 완료됐다고 표시하지 않는다.

저장 source, batch/operation ID, draft, 기준 본문, recovery run/checkpoint는
변경하지 않는다. 서버 쓰기, 권한 우회, 테스트 데이터 초기화, 전체 백업은 없다.

## 허용 조건

- 열린 전경 세션, 현재 로그인으로 준비된 권한, 미저장/조합/초안 저장 오류 없음.
- A–C의 활성 durable run과 연결된 queued 항목 정확히 1개. 요청/응답/송신 시도나
  해당 run의 checkpoint가 이미 있으면 거절. D 수신과 부분 수신/충돌도 거절.
- 동일 작품의 제한된 metadata GET과 고정 시험 문서의 body GET만 사용한다.
- 두 번의 구조 조회가 동일해야 하며, 그 사이 로컬 구조도 그대로여야 한다.
  이는 일치하는 반복 조회 검사이지 서버의 다중 테이블 원자 스냅샷 보장은 아니다.
- 고정 시험 본문의 원격 revision/UTF-8 바이트는 기존 기준과 같아야 한다.
- 프로젝트/UUID/부모/이름/경로/전체 순서 그래프를 검증한다. 변경 수용 범위는
  기존 `메인/메모장` 아래로 한정하고, 메모장 루트 자체와 그 밖의 항목은 유지한다.
  기존 ID 제거·범위 출입·리비전 역행·리비전 증가 없는 변경을 거절한다.
- 시험 문서의 구조, `메인/원고`와 상위 폴더, 원고 순서는 변경할 수 없다.
- 조회 후 실제 TXT·초안·로컬 기준·권한·source/run ID를 재검사하고 한 저널 행을
  추가한다. 이전 기록을 덮어쓰지 않는다. 재갱신은 기존 승인 기준에서도 후퇴하지 않는다.

## 이후 송신·수신

갱신 성공 후 prepared를 해제하고 다시 준비하도록 안내한다. 이후 매번
SQLite 기준 fingerprint가 기록된 원본 기준과 같은지 검증하고, 갱신된 구조와
현재 서버 **전체 구조**를 비교한다. 대상 본문 revision만 기존 방식대로
구조 비교에서 제외하며, 다른 문서의 revision 차이는 계속 차단한다.
SQLite 자체가 바뀌면 이전 비교 기준을 재사용하지 않는다.

갱신은 일반 앱의 자동 동기화나 구조 충돌 해결 기능을 대체하지 않는다.
NormalEditor 진단 후보의 로컬 검사 절차이며 wire 계약/Windows 구현/교차 플랫폼
입력 규칙은 변경하지 않으므로 별도 Windows 기능 검토는 요청하지 않는다.

## 검증 및 실기기 절차

- 1차: 입력창 6 + 비교 기준 9 + NormalEditor 53 + GeneralSync 70 = 138개 통과.
- 추가 실제 backend/SQLite + 가짜 HTTP 통합 테스트 포함 최종 141개 통과.
  원격 본문 변경, 두 구조 조회 사이 변경, 권한 해제 시 reference가 기록되지 않음을 확인했다.
  성공 경로에서는 SQLite·source·run을 유지하고 같은 batch로 beforeHTTP checkpoint에
  도달하며 본문 POST는 0회다. 테스트 빌드 warning/error 0건.
- 최종 실기기 빌드 성공, warning/error 0건. 동일 앱 식별자로 설치 완료.
- 실기기 갱신: 사용자 성공 문구 보고 및 sequence 84의
  `structureComparisonReferenceRefreshed` 기록 확인. 갱신 전 sequence 67과 비교해
  journal baseline·saves·recoveryRuns가 동일하며, 기존 A 저장 대기 1건은 queued,
  request/response 없음·attempts 0·checkpoint 0을 유지한다. reference 생성 확인.
  실제 SQLite/TXT를 이번 확인에서 별도로 다시 복사·대조하지는 않았다.
- 갱신 후 실기기 송신/beforeHTTP 도달은 아직 미확인.

실기기에서는 로그인 → 송수신 준비 → 구조 비교 기준 갱신 → 성공 문구 확인 →
다시 준비 → 저장된 변경 송신 1회 순서로 확인한다. 본문은 바꾸지 않는다.
기존 A run UUID/본문 해시를 유지하며 `NORMAL_RECOVERY_CHECKPOINT`에서 멈춘
뒤 기록을 검증하고 재실행·재개한다.
