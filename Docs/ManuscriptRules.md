# 원고 전용 바인더 규칙

## 범위

3-2단계의 `BinderRuleService`는 파일을 직접 바꾸지 않는 순수 Swift 판정 계층이다. 생성·이름 변경·이동·드롭·사용자 정렬 요청을 받아 허용 또는 사용자용 거부 이유를 반환한다. 실제 파일 거래와 메뉴 연결은 3-3단계에서 이 판정을 사용한다.

## 권 이름

- 원고 바로 아래에는 폴더만 둘 수 있다.
- 이름은 앞자리 0이 없는 ASCII 양의 정수와 `권`의 조합이다.
- `1권`, `10권`, `1000권`은 유효하다.
- `0권`, `01권`, `001권`, 전각·아라비아 숫자와 `1卷` 같은 유사 문자는 거부한다.
- 만들어진 권 이름은 변경할 수 없다.

## 화 이름

- 권 폴더 안에는 TXT만 둘 수 있다.
- 새 화는 세 자리 이상 ASCII 숫자, `화`, 소문자 `.txt`의 정규 이름으로 만든다.
- 1~999화는 `001화.txt`~`999화.txt`, 1,000화부터는 `1000화.txt`처럼 자릿수를 자연 확장한다.
- `000화.txt`, `01화.txt`, `0001화.txt`, `001화.TXT`, 전각·유사 숫자는 거부한다.
- 새 화 생성 시에는 제목 접미사가 없는 정규 이름만 허용한다.
- 생성 후에는 `001화 첫 만남.txt`처럼 제목을 덧붙일 수 있지만 기존 `001화` 접두사는 바꿀 수 없다.
- 화 번호는 권과 관계없이 작품의 원고 전체에서 중복될 수 없다.

## 이동·드롭·순서

- 원고 최상위 항목은 첫 번째에서 이동하거나 이름을 바꿀 수 없다.
- 원고 안의 권·화는 일반 카테고리로 나갈 수 없다.
- 일반 카테고리의 폴더·문서는 원고 안으로 들어갈 수 없다.
- 화는 유효한 다른 권으로 이동할 수 있지만 같은 화 번호가 이미 있으면 거부한다.
- 권은 원고 바로 아래, 화는 유효한 권 바로 아래라는 구조를 유지해야 한다.
- 원고 안의 권·화에는 사용자 순서를 적용하지 않고 숫자 자연 정렬을 사용한다.
- 일반 문서 영역에는 `PathPolicy`의 Windows 안전 이름·충돌 규칙 외의 원고 제약을 적용하지 않는다.

## 판정 우선순위

원고 구조 잠금은 일반 이름 충돌보다 먼저 판정한다. 예를 들어 `1권`을 이미 존재하는 `2권`으로 바꾸려 해도 “중복 이름”보다 “권 이름은 변경할 수 없음”을 먼저 알려준다. 이름을 바꿀 수 있는 요청에만 Windows 금지 이름과 대소문자·Unicode NFC 충돌 검사를 적용한다.

## 공유 규칙

Windows 작품 가져오기도 같은 파서를 사용한다. 따라서 앱 내부 규칙과 가져오기 보고서가 1,000화, 제목이 붙은 화, Unicode 유사 숫자를 서로 다르게 판단하지 않는다.
