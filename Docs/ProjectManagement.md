# 작품 관리 거래 — 2-3

## 공개 경계

`ProjectManaging`은 화면이 파일 시스템이나 SwiftData를 직접 수정하지 않도록 다음 작업을 한곳에 모은다.

- 작품 생성과 정렬된 목록 조회
- 마지막으로 선택한 활성 작품 복원
- 작품 이름 변경
- 사용자 지정 순서 저장
- 삭제 확인 값 생성과 삭제 대기 상태 전환·취소
- 작품 루트의 안전한 조회·진단에 사용할 `ProjectExportDescriptor` 생성
- 앱 시작 시 미완료 작품 거래 복구

`ManagedProject`는 기존 SwiftData `Project`와 로컬 목록 정책을 합친 값이다. SwiftData V1은 작품 ID·이름·생성·수정 시각을 계속 저장한다. 사용자 순서와 `deletionRequested` 상태는 작품 루트의 숨김 카탈로그에 저장하므로 V1 스키마를 변형하지 않는다.

## 생성 거래

1. Windows 호환 이름과 대소문자·NFC 충돌을 검사한다.
2. `Projects/.writerpad-create-<UUID>.tmp`에 전체 표준 구조와 `설정.json`을 만든다.
3. 생성 저널을 원자적으로 기록한다.
4. SwiftData에 작품 메타데이터를 저장한다.
5. 임시 작품 컨테이너를 정식 작품명 폴더로 한 번에 이동한다.
6. 작품 카탈로그와 마지막 작품을 갱신한 뒤 저널을 제거한다.

일반 실패는 임시·정식 폴더, SwiftData 메타데이터, 카탈로그를 모두 이전 상태로 되돌린다. 중단으로 저널이 남으면 다음 실행에서 임시 폴더와 메타데이터 조합을 확인해 승격을 완료하거나 불완전 생성을 제거한다. 같은 이름의 성공한 생성 요청이 다시 오면 기존 작품 ID를 반환하고 중복을 만들지 않는다.

## 이름 변경 거래

이름 변경 전에 이전·새 `Project` 값을 가진 저널을 기록한다. 작품 폴더 이동과 `설정.json` 이름 갱신 후 SwiftData 이름을 갱신한다. 어느 단계에서 일반 실패가 발생하면 폴더, 설정, SwiftData를 이전 이름으로 복구한다.

앱이 이동 중 종료되어 저널이 남은 경우 다음 실행은 다음 기준으로 처리한다.

| 디스크 상태 | 복구 |
|---|---|
| 새 폴더만 존재 | 설정과 SwiftData를 새 이름으로 맞추고 완료 |
| 이전 폴더만 존재, SwiftData가 새 이름 | 폴더 이동을 완료하고 새 이름으로 맞춤 |
| 이전 폴더만 존재, SwiftData가 이전 이름 | 롤백 완료로 판단하고 저널 제거 |
| 두 폴더 모두 존재하거나 모두 없음 | 임의 덮어쓰기를 하지 않고 저널을 보존해 오류 보고 |

## 순서·삭제·마지막 작품

- 카탈로그는 `project_id`, `user_order`, `deletion_requested_at`만 저장하고 원자적으로 교체한다.
- 순서 변경 요청은 현재 작품 ID 전체가 정확히 한 번씩 포함됐을 때만 반영한다.
- 삭제 확인 준비는 상태를 바꾸지 않는다. 화면 확인 후에도 작품 이름이 같을 때만 삭제 대기로 전환한다.
- 삭제 대기 전환은 작품 폴더와 SwiftData 메타데이터를 제거하지 않는다. 실제 이동·영구 삭제는 6단계 휴지통 정책에서 처리한다.
- 마지막 작품이 없거나 삭제 대기 중이면 첫 활성 작품을 선택하고, 활성 작품이 하나도 없으면 빈 화면으로 복원한다.

## 자동 검증

실제 원고를 사용하지 않고 매 테스트마다 새 임시 폴더와 인메모리 SwiftData를 사용한다. 생성 구조, 중복 요청 멱등성, Unicode 충돌, 생성 실패 롤백, 생성 중단 후 재실행, 이름 변경, 이름 변경 롤백·재실행 복구, 사용자 순서, 마지막 작품, 삭제 확인, 작품 루트 설명자를 검증한다.
