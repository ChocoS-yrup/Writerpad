# 바인더 데이터 제공 계층

## 범위

3-1단계는 바인더를 읽고 표시하는 기반만 구현한다. 폴더·TXT 생성, 이름 변경, 이동, 삭제와 원고 전용 규칙은 다음 단계에서 추가한다.

## 표시 구조

`메인` 바로 아래의 고정 폴더는 다음 순서로 먼저 표시한다.

1. 원고
2. 캐릭터
3. 설정집
4. 메모장
5. 흐름 정리
6. 복선
7. 장소
8. 휴지통

그 밖의 사용자 폴더와 TXT는 일반 항목으로 이어서 표시한다. 플롯과 메인 스토리 틀은 고정 항목이 아니며, 사용자가 만든 경우에만 일반 폴더로 표시한다. TXT는 디스크에서 `.txt`를 유지하지만 바인더 표시명에서는 확장자를 숨긴다.

## 지연 로딩

- 작품을 열 때는 `메인`의 직계 자식만 읽는다.
- 폴더를 펼칠 때 해당 폴더의 직계 자식만 백그라운드에서 읽는다.
- 접힌 형제 폴더의 내용은 미리 읽지 않는다.
- 펼침 상태는 SwiftData에 저장하며 다음 실행에서 필요한 가지까지만 순서대로 복원한다.
- View와 ViewModel은 `FileManager`를 직접 사용하지 않는다.

## 정체성 및 외부 변경 조정

파일 시스템 경로와 SwiftData의 문서 UUID를 분리한다. 다시 읽을 때는 다음 순서로 기존 정체성을 찾는다.

1. 정규화된 상대 경로와 종류가 같으면 기존 UUID를 유지한다.
2. 같은 부모 안에서 TXT의 경로가 바뀌었어도 SHA-256이 유일하게 일치하면 이름 변경으로 판단해 UUID를 유지한다.
3. 일치가 없으면 새 UUID를 만든다.
4. 사라진 항목과 그 하위 메타데이터는 제거한다.

해시가 같은 TXT가 여러 개라 판단이 모호하거나 폴더가 외부에서 이름 변경된 경우에는 잘못 연결하는 대신 새 정체성으로 등록한다. 앱 내부 이름 변경·이동의 UUID 보존 거래는 3-3단계에서 구현한다.

## 정렬과 내용 상태

- 고정 최상위 폴더는 고정 순서를 사용한다.
- 일반 항목은 저장된 사용자 순서를 우선하고, 동률이면 숫자를 인식하는 자연 정렬을 사용한다.
- TXT의 비어 있음/작성됨 표시는 파일 크기로 구분한다.
- SHA-256은 외부 변경 조정과 추후 무결성 확인을 위한 메타데이터로 저장한다.

## 검증

- 1,000화 작품 최초 진입 시 `메인`만 읽는지 검사
- 고정 최상위 8개 순서와 일반 플롯 폴더 처리 검사
- 권·화 자연 정렬, 사용자 지정 순서, `.txt` 숨김 검사
- 빈 TXT와 작성된 TXT 상태 검사
- 펼친 가지 복원 시 접힌 형제를 읽지 않는지 검사
- 외부 TXT 이름 변경과 새 파일 추가 후 UUID 조정 검사
- 파일 열거가 메인 스레드에서 수행되지 않는지 계측
