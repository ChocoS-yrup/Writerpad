- 현재 단계: 1~7단계 로컬 구현·실기기 기능 검증·M4 Release 성능 검증 완료
- 다음 단계: Windows v2와 Supabase 계약 확정 대기
- 제품 코드: SwiftUI 앱·SwiftData 메타데이터 저장소·테스트 타깃 기반 생성 완료
- Git: 로컬 저장소 초기화 완료
- Xcode: 26.6 설치·라이선스·최초 구성 완료
- Apple SDK: iOS/iPadOS 26.5 SDK 사용 가능
- Simulator: iOS 26.5 런타임과 iPad Pro·Air·mini·기본 iPad 기기 사용 가능
- 검증 기기: iPad Pro 11-inch (M5), iOS 26.5 시뮬레이터
- 성능 검증 실기기: iPad Pro 11-inch (M4), iPadOS 26.5.2, 7-6 Release 기준선·Time Profiler·Allocations 완료
- Bundle ID: `com.chocos.writerpad`
- Deployment Target: iPadOS 17.0
- Mac Catalyst: 설정 및 호환 빌드 확인 완료
- Windows 소스: `공유/`에 읽기 전용 참조 소스 제공됨
- Windows 테스트 작품: `집필모드/`에 1권·2권, 총 50화 제공됨
- Supabase: 1~7단계 범위에서 제외

## 요구사항 우선순위

서로 다른 문서의 내용이 충돌하면 다음 순서로 판단한다.

1. 사용자가 대화에서 확정한 최신 결정
2. `아팯_집필프로그램_코딩프롬프트_1-7단계.md`
3. `통합개발기획서_확인메모.md`
4. `아팯_집필프로그램_통합개발기획서.md`
5. 원본 전체 코딩 프롬프트

현재 확정된 예외는 다음과 같다.

- AI 집필도우미는 구현하지 않는다.
- 플롯과 메인 스토리 틀은 고정 바인더 항목이 아니다.
- 고정 바인더 최상위 항목은 8개다.
- TXT 전체 추출은 공백 포함 300자 미만 화에서 해당 화부터 중단한다.
- 바인더 너비와 TXT 추출 내용 옵션은 전 작품이 공유하고, TXT 추출 화수 범위는 작품별로 기억한다.
- 실행 취소·다시 실행은 `⌘Z`·`⇧⌘Z`, 화 이동은 `⌘[`·`⌘]`를 사용하며 `⌘⌥←`·`⌘⌥→`는 제공하지 않는다.
- 원고 내보내기는 백업·복원과 무관한 소장용 UTF-8 TXT·PDF만 제공하며, 작품 manifest와 재가져오기는 구현하지 않는다.
- Windows v2와 Supabase 규약은 확정 전까지 구현하지 않는다.

## 3-3 검증 결과

- 앱과 테스트 타깃을 Xcode가 정상 인식한다.
- iPad 시뮬레이터 빌드가 성공한다.
- SwiftData·경로 정책·TXT 저장·작품 관리·Windows 가져오기·바인더 명령을 포함한 자동 테스트 83개가 통과한다.
- 작품·문서·백업 ID와 상대 경로가 별도 타입으로 분리됐다.
- 이동·휴지통 이동 후에도 문서 ID와 작품 ID가 유지된다.
- Codable 메타데이터에 원고 본문 필드가 없음을 검사한다.
- 저장 상태는 이전 generation의 늦은 결과를 무시한다.
- 작품·문서·마지막 작품·좌우 문서·커서·바인더 너비·펼침 상태가 저장된다.
- 잘못된 부모와 작품을 넘는 부모 관계가 저장 단계에서 거부된다.
- 손상 메타데이터는 오류로 보고하며 원고 TXT에는 접근하지 않는다.
- Windows 금지 문자·예약 이름·끝 공백·마침표·제어 문자를 거부한다.
- 대소문자 비구분과 Unicode NFC 기준 충돌을 거부한다.
- 절대 경로·`..`·심볼릭 링크를 통한 작품 루트 탈출을 거부한다.
- 새 작품에는 플롯·메인 스토리 틀·전환직전 폴더를 만들지 않는다.
- 빈 파일·한글·이모지·대용량 원고가 UTF-8로 손실 없이 왕복한다.
- 임시 파일 쓰기·flush·표식·교체 실패에서 기존 원고가 보존된다.
- 문서별 저장 직렬화와 generation 검증으로 오래된 저장이 최신본을 덮지 못한다.
- TXT 저장 후 SwiftData 실패는 재조정 표식으로 남고 다음 실행에서 해시를 검증해 복구한다.
- 새 작품은 숨김 임시 폴더에 전체 구조를 만든 뒤 정식 경로로 승격한다.
- 같은 작품 생성 요청을 반복해도 기존 작품 ID를 반환하고 중복을 만들지 않는다.
- 작품 이름 변경 실패는 폴더·설정·SwiftData를 되돌리고, 앱 중단은 저널로 다음 실행에서 완료한다.
- 사용자 지정 순서와 마지막 작품이 재실행 후 복원된다.
- 삭제는 명시적 확인 후 삭제 대기 상태만 기록하고 작품 폴더를 지우지 않는다.
- 작품 목록·생성·이름 변경·순서 변경·삭제 확인 화면이 최소 연결됐다.
- Windows 작품 폴더 선택 후 치명 오류와 경고를 분리한 검사 보고서를 표시한다.
- 비 UTF-8, 중복 화, 잘못된 권·화 이름, 접근 불가, 숨김·알 수 없는 항목, 이름 충돌을 검사한다.
- 사용자가 보고서를 확인하기 전에는 가져오기를 시작하지 않는다.
- 가져오기는 앱 내부 임시 프로젝트에 전부 복사한 뒤 UUID·SHA-256을 일괄 등록하고 정식 경로로 승격한다.
- 중간 복사 실패와 메타데이터 실패에서 복사본·메타데이터를 모두 롤백하고 원본은 바이트 단위로 보존한다.
- 플롯·메인 스토리 틀은 고정 항목으로 승격하지 않고, `백업/전환직전`은 자동 병합하지 않은 채 원래 경로로 보존한다.
- 고정 최상위 8개를 정해진 순서로 표시하고 플롯 등 사용자 폴더는 일반 항목으로 표시한다.
- 작품 진입 시 `메인`만 읽고, 폴더를 펼칠 때 해당 직계 하위만 백그라운드에서 읽는다.
- 사용자 지정 순서와 숫자 자연 정렬을 적용하며 TXT 확장자는 화면에서만 숨긴다.
- 펼침 상태를 복원하고, 외부 TXT 이름 변경은 유일한 해시가 일치할 때 UUID를 유지한다.
- 1,000화 작품 최초 진입 시 하위 원고 파일을 미리 읽지 않음을 계측했다.
- `1권`·`001화.txt` 형식과 앞자리 0·ASCII 숫자·소문자 확장자 경계를 표 기반으로 검사한다.
- 1,000화부터 `1000화.txt`로 자연 확장하고 화 제목을 붙여도 기존 숫자+`화` 접두사를 보호한다.
- 같은 화 번호의 전역 중복, 원고 안팎 이동, 잘못된 드롭과 원고 사용자 순서 변경을 거부한다.
- Windows 가져오기가 동일한 권·화 파서를 사용해 1,000화·제목·Unicode 유사 숫자를 같은 기준으로 판정한다.
- 일반 폴더·TXT 생성, 이름 변경, 사용자 순서, 드래그 이동, 휴지통 이동이 파일과 SwiftData에 함께 반영된다.
- 이름·이동 후에도 대상과 인식된 하위 트리 ID를 유지하며, 200개 TXT 폴더 이동을 검증했다.
- 중간 종료 후 복구 저널로 파일 이동과 메타데이터 갱신을 완료하며, 중복은 덮어쓰지 않고 안전한 이름을 제안한다.
- 열린 문서, 자기 하위 폴더, 미확정·작품 밖 드롭을 거부한다.
- 길게 누르기·우클릭 메뉴와 드래그 앤 드롭을 바인더 화면에 연결했다.
- Mac Catalyst 호환 빌드가 성공한다.
- 실제 iPad 설치용 Apple 개발 팀과 서명은 아직 설정하지 않았다.

## 3-4 검증 결과

- 원고 최상위 컨텍스트 메뉴에서 `새 권 추가`를 실행할 수 있다.
- 유효한 최고 권+1과 25개 화 범위를 계산하며 0권·번호 공백·잘못된 권 이름·1,000화 경계를 처리한다.
- 고유 숨김 임시 폴더에 빈 UTF-8 TXT 25개를 준비하고, 전부 성공한 경우에만 정식 권 폴더로 승격한다.
- 권과 25개 화의 UUID·SHA-256 메타데이터를 SwiftData에 일괄 등록한다.
- 25개 각 파일 생성 실패와 정식 폴더 승격 직후 중단에서 전체 롤백 또는 재실행 복구된다.
- 기존 권과 전역 중복 화를 덮어쓰지 않고 작품별 동시 두 번째 생성 요청을 차단한다.
- 성공 결과가 바인더 새로고침·새 권 펼침·첫 화 열기 의도를 반환한다.
- 서버 작업은 만들지 않고 로컬 no-op 미래 변경 경계에 일괄 생성 사건만 전달한다.
- 3-4 전용 테스트 8개를 포함해 iPad Pro 11-inch (M5), iOS 26.5 시뮬레이터 전체 테스트 91개가 통과한다.
- Mac Catalyst 호환 빌드가 성공한다.

## 3-5 검증 결과

- 앱을 실행하거나 재실행하면 항상 작품 목록에서 시작하고, 작품을 열면 바인더·편집기 작업 화면만 표시한다.
- 가로 폭에서는 바인더와 편집기 영역을 함께 표시하고, 세로·좁은 Split View·Stage Manager 폭에서는 바인더 열기/닫기 버튼 하나를 제공한다.
- 상단 중앙의 작품 변경은 작품 목록으로 돌아가며, 검색·좌우 분할 자리표시자, 작은 로컬 저장 준비 배지와 추출·백업·설정 메뉴를 상단 도구막대에 배치했다.
- 8개 고정 바인더 항목의 순서, 항목 선택, 길게 누르기 메뉴를 작업 화면에 연결했다.
- Dynamic Type 접근성 크기·VoiceOver 식별자·키보드 포커스를 적용했다.
- 작업 화면의 `…` 메뉴에서 다크 모드를 켜고 끌 수 있으며, 끔 상태는 iPad 시스템 모드를 따른다.
- iPad Pro 11-inch (M5), iOS 26.5 시뮬레이터에서 단위 테스트 91개와 UI 테스트 4개, 총 95개가 통과한다.
- Mac Catalyst arm64 호환 빌드가 통과한다.

## 4-1 검증 결과

- `SmartTextView`와 `UIViewRepresentable` 기반 `iPadTextEditor`를 구현하고 실제 바인더 TXT 선택에 연결했다.
- 문서 ID와 외부 버전이 같으면 SwiftUI 업데이트가 UITextView 전체 본문을 다시 설정하지 않는다.
- 한글·이모지, UTF-16 커서·선택, 문서별 스크롤, first responder 요청, UIKit Undo/Redo와 일반 텍스트 붙여넣기 경계를 제공한다.
- 빈 문서 안내는 원문과 분리하고 검색 강조는 원문을 바꾸지 않는 확장 지점으로 유지한다.
- 로컬 UTF-8 TXT를 읽고 자동 저장 전까지 문서별 초안을 메모리에서 보존한다.
- 4-1 전용 단위 테스트 5개와 UI 테스트 1개를 추가해 단위 테스트 96개와 UI 테스트 5개, 총 101개가 통과한다.
- Mac Catalyst arm64 호환 빌드가 통과한다.

## 4-2 검증 결과

- `markedTextRange`가 존재하는 동안 외부 본문 적용과 즉시 문서 전환을 보류한다.
- 조합 중 여러 문서 선택에서는 마지막 요청 하나만 보관하고 조합 완료 후 전환한다.
- background에서는 pending 전환을 유지하고 foreground 복귀 후 처리한다.
- 포커스 상태 머신이 이전에 편집 중이던 경우에만 first responder 복원을 요청한다.
- 키보드 언어 강제 변경이나 Windows식 키 재전송을 사용하지 않는다.
- 4-2 전용 단위 테스트 2개를 추가해 단위 테스트 98개와 UI 테스트 5개, 총 103개가 통과한다.
- iPad Pro 11-inch (M5) 실기기에서 소프트웨어 키보드 한글 조합·겹받침·빠른 화 전환·앱 복귀 후 첫 입력과 Bluetooth 키보드 입력이 정상임을 확인했다.
- 외장 키보드 길게 누르기 반복 입력은 다른 앱에서도 동일하게 동작하지 않아 WriterPad 결함이 아닌 iPad 설정 상태로 기록했다.

## 4-3 검증 결과

- UIKit과 분리한 순수 Swift `TextRuleEngine`이 입력 문자열·UTF-16 범위·설정·조합 상태를 받아 최소 편집 연산과 새 선택을 반환한다.
- `'`, `"`, `[`, `(`, `{` 자동 쌍, 선택 감싸기, 동일 닫는 기호 건너뛰기, 빈 쌍 Backspace, 닫는 기호 앞 Enter 규칙을 구현했다.
- 한글·이모지 Character 경계가 아닌 잘못된 UTF-16 위치를 거부하고 조합 중·설정 off·다중 문자 붙여넣기를 우회한다.
- 스마트 편집은 전체 본문을 재할당하지 않고 필요한 `textStorage` 범위만 바꾸며 입력 한 번을 한 Undo/Redo 단위로 처리한다.
- 작업 화면 `…`의 설정에 `스마트 쌍 입력` on/off를 추가했다.
- 단위 테스트 103개와 UI 테스트 5개, 총 108개가 iPad Pro 11-inch (M5), iOS 26.5 시뮬레이터에서 통과했다.
- Mac Catalyst arm64 호환 빌드가 통과했다.

## 4-4 사용자 요청 구현 상태

- `...`을 중간점 말줄임표 `⋯`로 바꾸되 세 번째 마침표 직접 입력만 처리하고 붙여넣기는 제외한다.
- 최근 IME 조합 확정 범위의 `ㄴㄴ`을 `「」`, `ㄱㄱ`을 `『』`로 바꾸고 커서를 가운데에 둔다.
- `「」`·`『』`도 일반 괄호처럼 빈 쌍 Backspace 삭제와 닫는 부호 뒤 Enter를 지원한다.
- 소프트웨어 키보드가 두 번째 자음을 marked text로 유지하면 패턴 완성 시 해당 조합만 확정하고, 비-marked Bluetooth 입력은 두 번째 직접 자음 입력에서 처리한다.
- 별표 한 번은 정확히 `\n\n * * *\n\n`으로 바꾸며 붙여넣은 별표와 기존 원고는 변환하지 않는다.
- 전환선 바로 뒤 Backspace 또는 바로 앞 Delete는 전환선 전체를 삭제한다.
- 각 변환과 전환선 삽입·삭제는 한 번의 Undo/Redo 단위다.
- 깨끗한 DerivedData에서 단위 테스트 108개와 UI 테스트 5개, 총 113개가 iPad Pro 11-inch (M5), iOS 26.5 시뮬레이터에서 통과했다.
- Mac Catalyst arm64 호환 빌드가 통과했다.
- 수정 후 실제 iPad 소프트웨어·Bluetooth 키보드에서 `...`·`ㄴㄴ`·`ㄱㄱ`를 재확인하기 전에는 4-4 전체 검증 완료로 표시하지 않는다.

## 4-5 편집기 사용성 구현 상태

- 공백·줄바꿈을 포함한 Swift `Character` 기준 실시간 글자 수를 편집기 상단에 표시한다.
- 문서 전환 전에 UTF-16 커서·선택을 저장하며, 문서별 스크롤 위치는 편집 세션 동안 유지한다.
- 작업 화면 `…`의 설정에서 글꼴·크기·줄 간격·좌우/상하 여백·타자기 스크롤을 조절하고 재실행 후에도 복원한다.
- 타자기 스크롤은 커서를 중앙 부근에 유지하면서 문서 경계를 제한하고 시스템 동작 줄이기를 존중한다.
- 화면 설정은 TextKit 표시 속성에만 적용하며 원고 문자열·UTF-8 바이트·선택·Undo를 변경하지 않는다.
- 같은 화면 설정 상태로 다른 문서를 열어도 새 본문에 표시 속성을 다시 적용한다.
- iPad Pro 11-inch (M5), iOS 26.5 시뮬레이터 전체 테스트 118개와 Mac Catalyst arm64 빌드가 통과했다.

## 4-6 좌우 듀얼 편집기 구현 상태

- 가로 화면에서 좌우 편집기를 열고 활성 쪽만 강조하며 바인더 선택을 활성 편집기에 전달한다.
- 같은 `document_id`가 반대쪽에 열려 있으면 중복으로 열지 않고 기존 편집기를 활성화한다.
- 두 UITextView는 Undo·커서·스크롤을 독립 유지하고, 공유 초안 저장소로 미저장 본문 되돌림을 방지한다.
- 좌우 문서·활성 편집기·분할 여부를 작품별로 저장하고 다시 열 때 복원한다.
- 한글 조합 중 편집기 전환·분할 변경을 차단하며, 세로·좁은 폭에서는 분할 선호와 양쪽 상태를 보존한 채 활성 편집기만 표시하고 가로·충분한 폭에서 자동 복원한다.
- 작업공간 복원이 끝나기 전에는 편집 화면을 열지 않아 늦게 도착한 복원 결과가 새 선택이나 분할 상태를 덮어쓰지 않는다.
- 분할 닫기 전 양쪽 초안·커서·작업공간 상태를 보존하고 실패 시 닫기를 중단한다. 실제 TXT 즉시 저장 연결은 5단계 책임이다.
- 단위 테스트 117개와 UI 테스트 6개, 총 123개가 iPad Pro 11-inch (M5), iOS 26.5 시뮬레이터에서 통과했다.
- Mac Catalyst arm64 호환 빌드가 통과했다.

## 5단계 로컬 자동 저장과 상태 표시 구현 상태

- 마지막 입력 후 800ms 디바운스 자동 저장을 적용했다.
- 화·작품 전환, 분할 닫기, inactive/background, `Command+S`에서 최신 스냅샷을 로컬 TXT에 즉시 저장한다.
- 저장 I/O 중 새 입력이 들어오면 최신 dirty generation까지 다시 저장한 뒤에만 문서를 전환한다.
- 로컬 저장 실패 시 현재 화·최신 메모리 원고를 유지하고 전환이나 분할 종료를 중단한다.
- 배지는 아이콘·문구·VoiceOver로 `편집 중`, `로컬 저장 중`, `로컬 저장됨`, `로컬 저장 실패 · 재시도`를 구분한다.
- Supabase·영구 동기화 큐는 실행하지 않고 no-op 미래 변경 통지 경계만 유지한다.
- iPad Pro 11-inch (M5), iOS 26.5 시뮬레이터 전체 단위 테스트 127개가 통과했다.
- 실제 iPad의 배지 표시·저장 실패 재시도 UI 확인은 대기 중이다.
- 6단계 휴지통 즉시 갱신·계층 표시와 작품 간 백업 설정 공유를 iPad Pro 11-inch (M5) 실기기에서 확인했다.
- 같은 실기기에서 백업 미리보기·diff가 현재 원고를 바꾸지 않고, 복원 결과와 복원 전 백업이 재실행 후에도 유지됨을 확인했다.
- 단일 화 100만 자를 마지막으로 열어 둔 상태의 재실행 복원은 같은 실기기에서 약 4초를 기준선으로 기록했다.
