# 바인더 일반 명령과 복구 계약

## 범위

`LocalBinderCommandService` 는 바인더의 생성, 이름 변경, 이동, 사용자 순서, 휴지통 이동과 새 권 일괄 생성을 직렬화한다. 화면은 `BinderCommanding` 경계만 사용하며 `FileManager`나 SwiftData를 직접 변경하지 않는다.

명령 실행 전에 다음을 검사한다.

- `PathPolicy`: Windows 금지 문자·예약 이름·정규화 충돌·루트 탈출
- `BinderRuleService`: 원고 권·화 구조, 이동 경계, 자연 정렬
- 명령 서비스: 고정 최상위 항목, 자기 하위 이동, 열린 문서, 미확정·작품 밖 드롭

## 안정적인 ID

이름 변경과 이동은 대상 문서와 이미 인식된 하위 트리의 `document_id`를 바꾸지 않는다. 루트 항목의 부모 ID·사용자 순서와 전체 하위 항목의 상대 경로만 한 번에 갱신한다. 200개 TXT를 포함한 폴더 이동 테스트에서 201개 ID가 모두 유지됨을 확인했다.

## 복구 저널

파일 시스템과 SwiftData는 하나의 거래를 공유할 수 없으므로 작품의 `집필모드` 루트에 숨김 JSON 저널을 남긴다.

1. `prepared`: 이전·이후 문서 스냅샷과 경로를 저장
2. `files_applied`: 파일·폴더 생성 또는 이동 완료
3. `metadata_saved`: SwiftData 하위 트리 일괄 갱신 완료
4. 저널 제거

재실행 시 `prepared`는 원상 복구하고, `files_applied`는 메타데이터 갱신을 완료한다. `metadata_saved`는 파일 위치를 확인한 뒤 저널을 제거한다. 일반 오류는 즉시 롤백하고, 자동 복구가 불가능하면 저널을 보존해 수동 점검 경로를 잃지 않는다.

## 이름 충돌과 휴지통

같은 이름이 있으면 기존 파일을 덮어쓰지 않고 `이름 2.txt` 같은 Windows 안전 대안을 오류 결과에 포함한다. 휴지통 이동은 `메인/휴지통`으로 실제 항목을 옮기고, 각 인식된 하위 문서에 원래 상대 경로와 시각을 저장한다. 복원·영구 삭제·휴지통 비우기는 6단계 범위다.

SwiftData 필드는 프레임워크 자체의 삭제 상태와 이름이 충돌하지 않도록 `isTrashed`를 사용하며, 기존 저장 필드 `isDeleted`는 `originalName` 지정으로 이어받는다.

## 새 권 일괄 생성

원고 최상위의 `새 권 추가`는 디스크에 존재하는 유효한 `N권` 폴더 중 최고 번호에 1을 더한다. 권 번호가 없으면 1권을 만들며, 0권·앞자리 0·잘못된 이름은 최고 권 계산에서 제외한다. 화 범위는 `(권-1)*25+1...권*25`이고 999화까지는 세 자리, 1,000화부터는 자릿수를 늘린다.

고유 숨김 임시 폴더에 빈 UTF-8 TXT 25개를 모두 만든 뒤 폴더 이동 한 번으로 정식 권 이름에 승격한다. UUID 26개와 메타데이터는 메모리에서 먼저 준비하고 정식 폴더 승격 뒤 SwiftData에 한 번에 저장한다. 25개 파일의 어느 지점에서든 실패하면 임시 폴더·정식 폴더·미완료 메타데이터·저널을 모두 롤백한다. 승격 직후 앱이 중단되면 다음 실행에서 저널이 메타데이터 저장을 완료한다.

같은 작품의 동시 두 번째 요청은 대기열에 쌓아 다음 권을 만들지 않고 `volumeCreationInProgress`로 거부한다. 기존 권이나 전역 중복 화는 덮어쓰지 않는다. 성공 결과에는 바인더 새로고침, 새 권 펼침, 첫 화 열기 ID가 포함된다. 서버 작업은 등록하지 않으며 `FutureChangeNotifying`의 의미 사건만 호출하고 현재 구현은 로컬 no-op이다.

## 화면 연결

바인더 항목의 길게 누르기·우클릭 메뉴에서 새 폴더, 새 TXT, 이름 변경, 휴지통 이동을 실행한다. 원고 최상위에는 `새 권 추가`를 별도로 노출한다. 사용할 수 없는 명령은 비활성화하고 이유를 표시한다. 일반 항목은 드래그해 다른 폴더에 드롭할 수 있다.
