# iPad 내부 단계 실행 서비스

공통 계획 `general-body-20260912-v1`은 변경하지 않았다. Windows가 새로 확인하거나 실행할 일은 없어 전달 ZIP을 만들지 않는다. 실제 설치·기기 접근·실서버 요청은 모두 0회다.

## 구현

- `GeneralValidationStageService`가 수신, 저장 후 송신, 최종 수신을 각각 한 번 실행한다. 실제 네트워크·저장 기능은 주입하는 내부 서비스이며 기본 전송이나 자동 재시도는 없다.
- 수신은 documents/folders/tree_orders의 전체 열과 조회 순서를 고정한다. 기존 대조 문서와 폴더 11개·정렬 12개 전체를 미리 검토한 기준과 비교하고, 대상 본문 revision 1 또는 3·정렬 revision 2를 확인한다. 통과한 값만 immutable snapshot으로 전달하여 이후 본문 보충 조회가 추가 네트워크를 사용하지 않게 한다.
- 최종 HTTP 경계가 수락한 응답의 메모리 해시를 다시 대조한다. 전송 함수를 거치지 않은 가짜 성공, 응답 교체, 불완전한 로컬 반영 보고서는 완료할 수 없다.
- 송신은 로컬 저장 **전**에 영구 예약을 남긴다. 저장 후 실제 요청의 operation/batch/device/build ID를 유지하면서 고정 본문·계약과 비교한다. revision 2 성공 응답과 로컬 완료 처리가 모두 통과해야 단계가 완료된다. 저장·응답·반영 실패 시 기록을 보존하고 중단한다.
- 로컬 전환은 실행 전에 고정한 전체 SQLite/메타데이터/파일 해시와 정확히 비교한다. 저장 직후 revision 1 기준과 새 본문이 공존하는 상태를 별도로 검사한다. 변경 후 상태를 새 기준으로 무조건 채택하지 않는다. 변경 중 같은 실행의 HTTP 경계를 차단하고, 각 변경 단계의 권한은 해당 세대에서만 유효하다.
- 준비 화면 모델의 내부 생성 함수가 기존 인증·화면·작품 연결 검사, 실제 SQLite/파일 검사, 고정 앱 전용 기록 루트를 이 서비스에 연결한다. 기존 실행 객체와 새 서비스의 중복 생성도 거부한다. 앱 UI는 계속 준비 검사까지만 제공한다.

## 실행 전 남은 구성

제품 저장소의 compared save / 실제 큐 claim / snapshot apply / commit completion을 서비스의 변경 함수에 연결하고, 그 처리로 발생할 허용된 행·파일 변경의 예상 체크포인트를 실행 전에 생성·검토하는 구성이 남아 있다. 현재 격리 검사는 합성 데이터에서 예상 상태를 미리 고정하여 사용한다. 실제 제품 저장소의 전체 처리까지 종단 간 완료됐다는 의미는 아니다.

인증·handshake·실서버 조회 예산 및 실제 요청 고정, Windows 최종 후보 대조도 이후 실행 준비 범위다. 현재 코드가 기존 송수신 잠금을 풀거나 권한을 발급하지 않는다. 설치·실서버 요청은 구체적인 후보와 범위를 정리한 뒤 별도 승인받는다.
